# 24 · Staff roles and onboarding (before live accounts are created)

The hierarchy MCCI decided on 28 Oct 2026 (docs/21 §1) and how each person is brought onto MCCI Digital. Nobody gets
an account by any other route: the Secretary General invites each person by email from **Staff & Audit**; the person
sets a password and a Google Authenticator code (2-step login is required for every staff account).

## 1. Who does what

| Designation | Main work in the system | Key limits |
|---|---|---|
| **President (Signatory)** | Approves the Membership Committee the SG proposes (Committee page → "Approve committee") | sees everything else, changes nothing |
| **Secretary General** | Gives staff their access (view / edit / approve per area); proposes the Membership Committee; confirms certificate scans with conflicts | does **not** approve applications; does **not** export the register or download confidential files |
| **Membership Committee Convener** | Approves, declines (reason) or returns forwarded files on the Committee desk | must be the Convener of the committee the President approved |
| **Membership Committee Member** | Sees forwarded files; adds notes for the Convener (never shown to the applicant) | cannot decide |
| **IT Convener** | The only person who downloads original confidential files and exports the members register (CSV); platform settings | every download / export is logged |
| **Deputy Secretary — Membership** | Runs the membership desk; confirms certificate scans with conflicts | — |
| **Membership Officer** | Checks applications, returns them for correction, verifies documents, types the membership number (C-201 / A-786) and forwards; renewals, restorations, blacklist / whitelist; uploads certificate scans | views documents on screen only (watermarked, logged) — no download |
| **Accounts Officer** | Verifies receipts and counter payments (this activates the membership) | views receipts on screen only |
| **Services Officer** | Chamber services (C.O., letters) | views service documents on screen only |
| **Committee Secretary** | Meetings and minutes (a record) | does not decide applications |
| **Front Desk / Data Entry**, **Auditor (read-only)** | as before | no approvals |

## 2. Onboarding steps (in this order)

1. **SG account** — exists (the owner's account). Sign in, confirm the Google Authenticator code works.
2. **Invite the President** — Staff & Audit → "Invite staff by email" → designation *President (Signatory)*.
3. **Invite the Convener and committee members** — designations *Membership Committee Convener* / *Membership
   Committee Member* (they need Membership Committee access; other designations are refused as Convener).
4. **Invite the IT Convener** — designation *IT Convener*.
5. Each invited person opens the email, sets a password, scans the QR in Google Authenticator and signs in once.
6. **SG proposes the committee** — Committee page → "Assign committee": choose the Convener and the members → "Send
   to the President".
7. **President approves** — signs in, Committee page → "Approve committee". From now on only that Convener decides.
8. **Acceptance check through the real screens** (owner's instruction): with the real President and Convener
   accounts, run one demo application through forward → Convener's desk (a demo file can be declined or returned,
   never approved) and one real test applicant agreed with MCCI through approval → voucher → Accounts verification →
   active membership. Record the result in docs/23.

## 3. What staff will notice
- Documents open on screen with the viewer's name and the time across images; there is no "download" button except
  for the IT Convener. Every view is in the access log (Staff & Audit).
- The Committee desk shows only to staff with Membership Committee access; only the Convener sees the decision buttons.
- A proposer / seconder only presses Approve in their own portal (no code, no signature).
